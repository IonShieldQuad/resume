05 Interview Log

How do you use AI in your workflow?

I work across several agentic coding tools — Kun, OpenCode, Codex and Orca — for planning, implementation and review. My primary tool, Kun, is tuned for DeepSeek, which gives a high cache hit and a low cost per token. Whatever the tool, my workflow stays the same:

  1. 01 Write the specification.
  2. 02 Analyse the project.
  3. 03 Build an implementation plan (with a pre-mortem), refine it, discuss missed details.
  4. 04 Execute each step of the plan.
  5. 05 Test and verify the work (manually).
A hard problem you solved?

I wrote an optimisation algorithm that fetched data over an API. To avoid calling the API repeatedly, results were cached in a hash table — but the native way of comparing two objects was broken and always returned false, so caching silently never worked. I found it by attaching a profiler and wrote my own hashing / comparison function for those objects.

Clarifying questions you would ask?

About the project itself, the languages and stack, the concrete specification, what is in my responsibility and what is not, and the deadline. Then I would draft an implementation plan with intermediate milestones / checkpoints.

What does “done well” mean to you?

Code that works, is tested, is well optimised (speed / memory) and is clearly understandable to other team members.

How do you handle failure?

During my studies I ran into health problems and realised I could not carry a whole project by myself. I wrote up why, and scaled the goal down — I delivered a smaller part instead of the full project.

05 Лог собеседования

Как вы используете ИИ в работе?

Работаю с несколькими инструментами агентного кодинга — Kun, OpenCode, Codex и Orca — для планирования, реализации и проверки. Основной инструмент Kun оптимизирован под DeepSeek: высокий cache hit и низкая стоимость за токены. Какой бы инструмент ни использовался, процесс один:

  1. 01 Задание ТЗ.
  2. 02 Анализ проекта.
  3. 03 План реализации (с pre-mortem), корректировка, обсуждение упущенных деталей.
  4. 04 Пошаговое выполнение каждого пункта плана.
  5. 05 Тестирование и проверка работы (вручную).
Сложная проблема, которую вы решили?

Разрабатывала алгоритм оптимизации, который брал данные через API. Чтобы не вызывать API повторно лишний раз, кешировала результаты в hash-таблице — но нативный способ сравнения двух объектов был сломан и всегда возвращал false, поэтому кеширование молча не работало. Обнаружила это через профайлер и написала собственную функцию хеширования / сравнения для этих объектов.

Уточняющие вопросы на собеседовании?

Спросила бы про сам проект, языки и стек, конкретное ТЗ, что входит в мои обязанности, а что нет, и дедлайн. Затем составила бы примерный план реализации с промежуточными дедлайнами / точками сверки.

Что для вас «сделано хорошо»?

Код — работает, протестирован, достаточно оптимизирован (по скорости / памяти) и понятен другим членам команды.

Как справляетесь с неудачами?

Во время обучения возникли проблемы со здоровьем, и я поняла, что не смогла бы вытянуть проект целиком. Написала объяснение почему и снизила цель — реализовала часть поменьше, а не весь проект.
